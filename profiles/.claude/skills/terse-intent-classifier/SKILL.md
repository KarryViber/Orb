# 短指令作用层判定协议

> 来源：04/17、04/18、04/19 连续 3 天夜间反思升级行动项。根因：短输入省略了"作用对象"和"作用层"，直接按最新话题执行容易错层（把记忆层的事当运行层处理，或把架构层的事当配置层处理）。

## 触发条件

消息 ≤15 字 且 满足其一：

- **指代词**：含「这个 / 那个 / 上面 / 刚才 / 它 / 那条 / 这条」
- **动词型短指令**：以「改 / 删 / 切 / 跑 / 停 / 加 / 去掉 / 补 / 关 / 开」开头
- **元问句**：含「更优雅 / 更好 / 有没有办法 / 有没有更 / 能不能」

同时满足「thread 历史里有多个候选对象」时强制触发；thread 内只有唯一明显对象可以跳过。

## 动作

**必须先输出一行作用层判定，再动手。**

格式严格：

```
[层] {记忆层 | 配置层 | 运行参数层 | 外部动作层 | 架构层}
[对象] {具体文件 / 具体规则 / 具体行为}
[下一步] {执行 | 先澄清 | 写进记忆}
```

## 层的定义

| 层 | 典型对象 | 典型短指令 |
|---|---|---|
| **记忆层** | `~/.claude/projects/.../memory/*.md`、`~/Orb/profiles/<your-profile>/data/lessons/*.md`、holographic facts | 「记住这个」「忘掉那条」「改一下那条规则」 |
| **配置层** | `~/Orb/config.json`、cron-jobs.json、`.claude/settings.json`、hooks | 「把这个 cron 关掉」「加个权限」「改一下 trigger」 |
| **运行参数层** | 当前任务的 model/effort、--append-system-prompt、单次会话行为 | 「跑一下」「切到 sonnet」「再试一次」 |
| **外部动作层** | Slack 发送、API 调用、文件对外交付、git push | 「发出去」「推上去」「确认」 |
| **架构层** | `~/Orb/src/*`、adapter 接口、IPC 协议、lib/* | 「改一下这个架构」「换种方式实现」「重构这块」 |

## 判断不明 → 直接反问

不猜。反问模板（≤30 字）：

> 你指的是 A（{层}/{对象}）还是 B（{层}/{对象}）？

## 范围倾向：窄化 > 扩大（更常见的误判方向）

判范围时，**默认错误倾向是把范围缩窄到子集**，不是放大到全局。本周 05/01「考虑下目录架构」被缩到 `test/` 一个子目录就是反例（Karry 纠正：「我并不是只针对 test，是整个 orb 的一级目录」）。

规则：
- 短指令含「目录 / 架构 / 整体 / 全部 / 一级」类抽象名词 → 默认 = 全局，不要自动缩到上一条 thread 提过的某个子项
- 不确定范围时反问偏向：「是 X 整体还是只针对 X 下的 Y？」（先问全局再退到子集），**不要**反问「是 X 下的 Y 还是 X 下的 Z？」（这样把 Karry 锁死在子集里）
- 上一轮 thread 刚处理过子项 ≠ 这一轮还在子项；抽象名词出现就该重置范围

## 信号词：升结构层 / 探针类（不是客套）

| 短信号 | 真实含义 | 应对 |
|---|---|---|
| 「确认下」「以防万一」「需要收口吗」「帮我审计下」 | 切到结构层 / audit-first，怀疑当前修法不到根 | 立即停手，按 `debug-audit-on-second-miss` 出 audit；不要解释当前 patch 为什么对 |
| 「好了吗」「完成了吗」「好了吧」「跑完没」 | truth-ladder 探针，怀疑「attempted ≠ confirmed」失守 | 按 `truth-ladder` 重跑源端验证，不要回看 thread 历史断言 |
| 「就 X 别动其他」「只动 X」 | 精确边界划定，禁止顺手扩大 | 范围严格锁死到字面，邻近的 dead code / 风格不一致一律不动（呼应 surgical changes 偏好）|

## 反例

**错（04/18）**：
- 用户：「有哪些值得动手」（在 cron 输出 thread 下）
- 错误理解：按工作项目维度作答
- 正确理解：[层] 运行参数层；[对象] 本 cron 产出的行动项；[下一步] 执行

**错（首见 04/17）**：
- 用户：「改一下」
- 错误做法：直接按最新消息推断改什么
- 正确做法：[层] ?；[对象] ?；[下一步] 先澄清

**错（05/01 — 窄化倾向）**：
- 用户：「考虑下目录架构」（thread 历史刚处理过 `test/` 重构）
- 错误做法：缩到 `test/` 一个子目录作答
- 正确做法：抽象名词「目录架构」= 整个 orb 一级目录；不确定就反问「整体一级目录还是某个子目录」

## 与其他 skill 的关系

- `dm-routing`：DM→频道路由，正交（路由解决"去哪"，本 skill 解决"改哪层"）
- `execution-discipline`：本 skill 是「上下文先行」条目的具体化操作手册
- `debug-audit-on-second-miss` / `truth-ladder`：本 skill「信号词」表里的「确认下」「好了吗」分别是这两个 skill 的触发探针
